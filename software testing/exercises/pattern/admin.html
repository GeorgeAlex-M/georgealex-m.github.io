📋 Pattern Specifications
  1. Accept three hexadecimal integers (including positive and negative)...
  2. ...that ascend in value from left to right.
  3. There may be a "+" symbol preceding positive numbers.
  4. The integers must be delimited by whitespace, comma, period, or colon.
  5. There also may be leading or trailing whitespace on the test case string.
  6. If a non-whitespace delimiter is used, there may also be leading (but not trailing) whitespace on each of the three integers in the string.
  7. More than one "-" or "+" in a row causes number to be treated as a zero.
  8. Encoded characters are transformed by HTTP (e.g. %20 is turned into a space).
  9. HTML is not stripped out, which can disrupt the front end.
  10. Any text appended to the end of a test case string will be ignored if it starts with whitespace.
🔬 Test Design Guide & Solution

This guide demonstrates how to use common software test design techniques to systematically understand and test the 10 pattern rules.

1. Key Test Design Techniques

  • Equivalence Partitioning (EP): Dividing input data into partitions from which test cases can be derived. Assumes all values in a partition behave the same. E.g., for a hex digit, valid hex chars (0-9, A-F) form one partition, invalid chars (G-Z, !, @) form another.
  • Boundary Value Analysis (BVA): Testing at the edges or boundaries of equivalence partitions. E.g., if a number must be 1-100, test 0, 1, 100, 101. For this pattern, boundaries might relate to the number of characters, number of signs, etc.
  • Decision Table Testing: Useful when behavior depends on multiple conditions. For example, Rule 6 depends on the type of delimiter AND the presence of whitespace.
  • Negative Testing: Designing test cases that are expected to fail or produce error conditions. Crucial for ensuring robustness and correct error handling.
  • Exploratory Testing: Simultaneous learning, test design, and execution. Useful for discovering edge cases not immediately obvious from specs.

2. Applying Techniques to Discover the Pattern (Rule by Rule)

Let's assume we start with the given examples (e.g., "2, 4, 6" on index.html) and the 10 rules. Our goal is to confirm each rule.

Rule 1: Accept three hexadecimal integers (positive/negative).

Techniques: EP, BVA, Negative Testing.

  • EP (Valid): 1 2 3, A B C, 10 1A 2B. Test negative: -A 0 10.
  • EP (Invalid Chars): 1 2 G (should fail).
  • BVA (Number of Parts): 1 2 (fail), 1 2 3 4 (test Rule 10 interaction).
Rule 2: ...that ascend in value from left to right.

Techniques: EP, Negative Testing.

  • EP (Valid): 1 2 3, -10 0 10.
  • EP (Invalid - Not Ascending): 3 2 1 (fail), 1 3 2 (fail).
  • EP (Invalid - Equal): 1 1 2 (fail).
Rule 3: There may be a "+" symbol preceding positive numbers.

Techniques: EP.

  • EP (With '+'): +1 +2 +3.
Rule 4: The integers must be delimited by whitespace, comma, period, or colon.

Techniques: EP.

  • EP (Valid): 1 2 3, 4,5,6, 7.8.9, A:B:C.
  • EP (Invalid): 1;2;3 (fail).
Rule 5: There also may be leading or trailing whitespace on the test case string.

Techniques: EP.

  • EP (Valid): 1 2 3, 1 2 3 , 1 2 3 .
Rule 6: If a non-whitespace delimiter is used, leading (not trailing) whitespace on integers.

Techniques: EP, Decision Table.

  • EP (Valid): 1, 2, C, A . B . 1C.
  • Refresher: "Trailing" refers to space after the number but *before* a non-whitespace delimiter (e.g., 1 ,). This is handled because 1 becomes the token.
Rule 7: More than one "-" or "+" in a row causes number to be treated as a zero.

Techniques: EP, BVA.

  • EP (Valid, becomes 0): ++0A 0B 0C (0, 11, 12 - matches), --1 2 3.
  • BVA (Single sign - not zero): +1 2 3.
Rule 8: Encoded characters are transformed by HTTP (e.g. %20 is turned into a space).

Techniques: EP.

  • EP (Valid): 1%202%203 (becomes "1 2 3"), 1%2C2%2C3 (becomes "1,2,3").
Rule 9: HTML is not stripped out... (but may still parse if HTML is in ignored part).

Techniques: EP.

  • EP (Valid - HTML in ignored part): 1 2 3 ignored (matches).
  • EP (Invalid - HTML disrupting number): 1 2 3 (fails).
Rule 10: Any text appended ... will be ignored if it starts with whitespace.

Techniques: EP.

  • EP (Valid - ignored): 1 2 3 ignore this.
  • EP (Invalid - not ignored): 1 2 3ignorethis (fails).

By systematically testing each rule, you confirm your understanding. The "Comprehensive Example (All Rules)" from the User Rule Breakdown modal demonstrates this synthesis:
